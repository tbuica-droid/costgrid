01 — How it works

Three changes, none of them in your application logic.

CostGrid is a proxy. It forwards each call to the same provider with the same body, streaming included, then reads the token counts back out of the response.

01  Point the base URL

client = Anthropic(
  base_url="https://costgrid.acme.dev",
  api_key="unused",
)

Your provider key lives in the gateway, so the services calling through it never hold one. Anthropic and OpenAI today.

02  Label the traffic

x-costgrid-agent: chat-bot
x-costgrid-department: Support

Two optional headers turn one provider invoice into per-team, per-feature chargeback. Unlabelled calls are still metered — as unattributed, a visible line rather than a silent gap.

03  Set the rules

costgrid policy budget \
  dept:Engineering 500.00 \
  --fallback claude-haiku-4-5

Budgets per team or agent, model allowlists, output caps. Start every rule in monitor to watch what it would have done.

Time to first metered call about five minutes, on your own machine
02 — What you get

Reporting a saving is advice. Making one is a product.

Exact metering, not estimates

Token counts come from each provider’s own usage object. Five buckets priced independently — input, output, 5-minute and 1-hour cache writes, cache reads — because a cache-heavy workload is mispriced by anything that lumps them together. 53 models, re-verified against the published tables.

no guessing
Budgets that don’t break production

The reason nobody turns on a hard cap is that it breaks the product at 3am. A CostGrid cap can downgrade instead: over-budget traffic is served by a cheaper model and keeps answering, with a response header saying so. It refuses any substitution it cannot make safely — across providers, or to a model it cannot price.

the difference
Savings you can audit

A routing rule moves matching traffic to a cheaper model and records the counterfactual: what those exact tokens would have cost on the model the caller asked for. Realised savings are reported separately from dry-run ones, so the number can be checked rather than believed.

measured
A statement finance can reconcile

A closed calendar month in UTC — not a trailing window — because that is how the provider invoices. Spend by team with movement against last month, budget status, what routing saved. Text, CSV or JSON.

CSV export

Every figure is computed in integer nanodollars. Nothing rounds until it is displayed.

05 — Straight answers

The questions you are about to ask.

Does our prompt and response data go to you?

No. You run CostGrid inside your own infrastructure — there is no CostGrid service in the middle. Bodies are forwarded to the provider and streamed back untouched. What is stored is token counts, model names, cost and your labels. Not prompts, not completions.

What does it do to latency?

One local network hop. Streamed bytes are passed through as they arrive rather than buffered, so time-to-first-token is essentially unchanged.

What happens if CostGrid goes down?

It is in the request path, and pretending otherwise would be dishonest: if it is down, those calls fail. That is the price of being able to refuse a call rather than report on it afterwards. Run it beside the service that calls it, and keep every rule in monitor until you trust it.

Are the prices right?

53 models across Anthropic and OpenAI, checked against the providers’ published tables by a script that fails on a discrepancy or a stale verification date. The dashboard says so on the page when the catalog is over 45 days old — a stale catalog does not fail loudly, it just bills last quarter’s rates.

What is it bad at?

Bedrock and Vertex are not supported yet — direct Anthropic and OpenAI only. It governs API spend, not seat licences: if your AI bill is people using a chat product in a browser, there is nothing here to meter. And it is one node on SQLite today, which is fine for a team and not yet a high-availability deployment.
